# 局域网 Dashboard 与接口风险门禁

## 范围与安全边界

Dashboard 是本地 RobotRuntime 的操作界面，不直接连接 SDK、DDS 或 ROS。浏览器只请求服务端注册的 typed operation；调用者身份和角色来自服务端会话，不能由 request body 提供。

风险等级与调用入口独立配置：

| 等级 | Agent | Dashboard | 门禁 |
|---|---|---|---|
| `normal` | 按 capability caller policy | 按 capability caller policy | 每次执行参数、机器人状态与适配器检查 |
| `confirm` | 可提出 | 已登录操作员确认后可执行 | Agent 必须经过无工具 AI 复核；没有 reviewer、复核拒绝或 digest 不一致时拒绝。未配置 reviewer 时，Dashboard 用本次操作员确认代替 AI 复核，参数绑定和适配器检查仍然生效。配置了 reviewer 时，Dashboard 同样先做 AI 复核 |
| `high` | 禁止 | 仅认证的 Dashboard operator | 本次操作明确确认、当前账户密码复核、绑定 command/task/args/policy 的确认标识和适配器再次校验 |

等级划分原则：Go2 这类成熟的量产机器人，大部分动作不属于高危，默认定为 `normal`。`confirm` 只留给设备自身保护无法消除后果的动作，典型例子是后空翻这类需要大面积空旷场地、避障也无法避免风险的动作，由操作员做一次二次确认。`high` 再收窄到关闭安全保护的开关这类操作。定级看的是失败后果能否被设备自身的保护限住，而不是动作看上去是否激烈。Go2 profile 已按这一原则逐项复核并放宽，当前结果见下文「实施状态」；定级理由写在 profile 的说明里，不依赖提示词。

AI 复核与人员确认是不同记录和门禁。语音、文字任务或 UI 可见性不会自动授予权限。缺失/冲突策略、未知接口和过期状态默认不可调用。SDK 方法须逐项映射到固定 typed operation，不支持任意 SDK 方法透传。

`SwitchSet(false)` 这类关闭安全保护的操作默认维护专用或禁用。只有相应 SDK/固件行为、运行前置条件、停止与恢复流程经过验证后，才可讨论是否作为 high Dashboard 操作开放。

## 无屏机器人的确认通道

绝大多数机器人没有屏幕，确认不能依赖点击。风险等级只决定走哪一档流程，不决定结论：

| 情形 | 通道 | 强度 |
|---|---|---|
| 常规动作（`normal`） | 不确认 | — |
| `confirm` 且动作可逆 | 语音单字或手势一次，10 秒窗口 | 低 |
| `confirm` 且动作不可逆 | 唤醒词前缀加确认词，或语音与手势同时具备，10 秒窗口 | 中 |
| 关闭安全保护、修改系统 | Dashboard 认证加当前账户密码，绑定具体动作且限时限额 | 高 |

可逆与否按物理特征判定，不按动作名清单：离开地面的（前后空翻、向前跳、向前扑、倒立、自由弹跳）、产生位移的（行走、移动）、改变安全配置的（避障开关、自动恢复开关）算不可逆；原地改变姿态或步态的（站立、趴下、坐下、转向、舞蹈）算可逆。新动作按同一特征归类，不需要维护名单，也不会因为漏登记而默认可执行。

### 复核 AI 必须说明风险原因

需要确认时，复核 AI 先讲清要做什么动作、影响范围多大、哪一部分不可逆、拒绝的后果是什么。讲不清楚就不该要求确认。复核结论只回答风险，不替操作员做拒绝：它把风险报给人类，而不是连问都不问就否定。可以用更简单的话重讲，也可以把细节放到 Dashboard 或 App，但语音里至少要有一句人能直接听懂的风险说明。否定式回复必须给出可操作的下一步，不能只说「不行」。

### 语音二元确认

确认词是闭集，只有「确认」和「取消」，由本地 KWS 判定，不交给语言模型理解上下文：

- 播报期间关闭 KWS，播报结束后再加约 200 毫秒静音保护期。机器人自己念出的提示常含有待选词，不静音就会被识别成用户回答；提示语措辞也应避开这两个词本身。
- 10 秒窗口从播报结束加保护期之后开始计时，是独立计时器，不复用 `follow_up_seconds`（默认 8 秒，用于普通追问），也不因环境说话而延长。
- 只认紧随提示之后的第一句；只认机器人本地麦克风，不认 Dashboard 通话音轨；按声源方向门控；多人同时说话按「没听到」处理。
- 不可逆动作要求唤醒词前缀，例如「索拉，确认」，单独一句「确认」不生效。
- 只提示一次。窗口内没有有效确认就放弃，不默认同意，不自动再问。超时说「没有听到确认，已放弃」，收到「取消」说「已取消」。进入监听状态时给一声短提示音或一个灯色。

### 手势确认

- OK 手势表示同意；五指张开朝向摄像头的阻拦手势是全局停止手势，在确认窗口之外同样生效。
- 手势要求保持至少 0.5 秒、正面朝向摄像头、距离在有效范围；单帧不算。
- 不可逆动作不能只靠手势：一张 OK 手势的照片就能骗过一次识别，所以语音与手势同时具备才放行。

### 没有证据与反向证据

人工补充只对「没有证据」有效，对「反向证据」无效：

- 没有证据：例如从没测过后方。用户口述「我确认后方没有障碍」可以补上，但这条陈述带时间和来源，执行时按年龄判断是否仍然有效。
- 反向证据：例如实测后方 1 米有人、电量 5%。说什么都不能覆盖，只能走 Dashboard 认证加密码。

这条区分是防退化的关键。否则「人说 OK 就能执行」迟早会变成「人能指挥机器人翻到别人身上」。

### 复核结论与执行条件分开

复核同意不等于执行条件仍然成立：机器人可能已经移动，电量可能已经变化。复核可以附带确定性条件（后方净空 ≥ 2 米、电量 ≥ 20%、半径 2 米内无人），由本地安全层在执行时逐项重查，任一不满足即停止并报告实际结果。语义判断留在云端，确定性检查留在本地。

### Dashboard 确认的约束

Dashboard 确认只用于高风险和系统修改，并且绑定具体动作或动作类别，不绑定到人：

- 时长上限（例如 5 分钟）和次数上限（1 次或 3 次），到期自动撤销。
- 任务完成、会话断开、页面关闭都自动撤销。
- 页面显示倒计时；机器人侧用语音或指示灯同步提示，因为屏幕不在机器人身上。

### 误拒的度量与可见性

误拒可以预期，需要度量而不是回避。用同一批带标签的案例统计「通过 / 需要证据 / 否决」的比例，核对拒绝理由是否指向真实缺口，并把复核结论、缺失的证据项和人工判决都写进活动记录。操作员可以在记录里看到为什么要确认，并直接覆盖，覆盖本身留痕。

## Dashboard 页面

- 总览：robot_id、型号、连接/健康、活动任务、最近反馈和策略/profile 版本。
- 控制：对话界面提交自然语言，由语言模型根据技能介绍选择技能。以 `/技能名` 或 `/技能名 参数=值` 开头的文本才在本地直接调用，不再对自由文本做关键词匹配。Agent 调用了动作时，在对应气泡下显示动作名称和技能 ID；拒绝时只显示理由。可用操作与对话水平并排，默认折叠，展开后在面板内滚动查看。操作表单显示参数单位、范围和风险；不可用能力展示禁用原因。
- 能力目录：operation、风险、允许调用入口、参数 schema、超时、可中断性、策略来源和可用状态。
- 活动：任务与命令状态、AI 复核结论、操作员确认状态和适配器结果。
- 监控：勾选后同时查看运行日志、麦克风输入波形和播放输出波形。运行日志来自当天的 `logs/YYYY-MM-DD.log`，唤醒、识别、提交运行时和技能执行结果也写在这里。总览页不再展示语音日志。格式和隐私边界见[运行日志](17-runtime-log.md)。
- 设置：大语言模型、音频和登录账户。模型设置只保存一条云端路径，字段为 provider、base_url、model、timeout 和 API key。音频设置写回 `config/voice.json` 的机器人名称、唤醒短语、语言、输入/输出设备和会话时间；模型 ID 仍只能使用静态 registry 中的值。登录账户替换原先的操作员 PIN。
- 语音目标设计：本地 PASSIVE 唤醒和 Dashboard WebRTC 通话共享 Voice Service；通话开始前须确认机器人本地麦克风已经关闭并释放，只有此后才接收浏览器音轨。登录或打开页面不自动请求麦克风权限。

## Dashboard API

- `GET /api/session`：当前会话状态。
- `POST /api/login`、`POST /api/logout`：操作员账户和密码登录/退出。请求体提供 `username` 与 `password`，不接受 PIN。
- `GET /api/settings`：已登录操作员读取模型、音频和账户设置。响应只包含账户名，不包含密码摘要或 API key。
- `POST /api/settings/llm`、`POST /api/settings/audio`：保存云端模型路径和音频配置。留空的 `api_key` 保持原值；显式空字符串会清除密钥。
- `POST /api/settings/accounts`、`POST /api/settings/accounts/delete`：新增或更新账户，以及删除其他账户。两次都要提交当前登录账户的密码。不能删除当前登录账户，也不能删除最后一个账户。
- `GET /api/dashboard/overview`、`GET /api/capabilities`：只读总览和能力目录。
- `GET /api/logs`：已登录会话读取当天运行日志。可选 `limit`（1 到 200，默认 100）和 `level`。返回原文文本行。
- `POST /api/tasks`：提交自然语言任务。它与本地语音最终转写、Dashboard 通话最终转写进入同一条 `openrobotsoul-dialogue` 规划入口（链接 `third_party/picoclaw` AgentLoop，会话键由宿主按认证账户、入口与对话生成，不使用裸 `dashboard`，见 [18](18-picoclaw-dialogue-context.md)），再经 capability surface 和 runtime 策略处理。编码用的 Go 版 PicoClaw CLI 不参与这次规划。
- `POST /api/actions/prepare`：服务端校验 caller、skill、schema、参数边界与当前策略，建立短时挑战；客户端不能设置 caller/risk/确认结果。
- `POST /api/actions/execute`：提交挑战 ID。服务端原子消费挑战，重验策略与 digest；高危操作还需再次输入当前账户密码，然后通过 `InvocationContext` 调用 Runtime。

挑战绑定认证 session、robot、task/trace、skill、规范化参数、风险与 callers、profile version、有效期。挑战仅使用一次；登出、过期、重放或策略变化都拒绝。失败不会调用 adapter。

## 认证和部署

初版服务使用标准库 HTTP server，不增加运行依赖。绑定 loopback 可用 HTTP 做本地开发；绑定明确的局域网 IP 必须提供 TLS certificate/key。拒绝 `0.0.0.0`、`::` 通配监听。Session cookie 为 HttpOnly/SameSite，写请求需要 CSRF token 并校验 Host/Origin；登录和高危操作的密码复核都有限速。

操作员账户写入 `config/operators.json`。账户名明文保存。密码不以明文或 MD5 保存，每条记录使用独立盐的 PBKDF2-HMAC-SHA256（200000 次）单向摘要，文件权限为仅当前用户可读写。首次启动如果文件里没有账户，从 `ROBOTSOUL_DASHBOARD_USER` 和 `ROBOTSOUL_DASHBOARD_PASSWORD` 创建；未设置时在终端询问用户名，并隐藏输入密码。文件里已经有账户时，启动过程不再读取这两个环境变量。密码和 API key 不写入日志。

云端模型配置写入 `config/llm.json`，权限同样限于当前用户。API key 需要原样提交给模型服务，因此文件中保留密钥本身，但 `GET /api/settings` 和页面只报告密钥是否已设置，不回显密钥。`config/operators.json` 和 `config/llm.json` 不纳入版本控制。

Dashboard LAN TLS 是控制操作的部署要求。浏览器麦克风 API 还要求 secure context；Dashboard 已接入认证后的 WebRTC 调用/应答/挂断 API，浏览器只在用户明确发起通话后申请麦克风。HTTP 只能用于 loopback 原型，不应控制真实机器人。当前代码和自动化测试不代表真实 Go2 的音频设备、ARM64 PyAV/WebRTC 与弱网行为已经验收。语音通话的音源互斥、通话断线期间本地麦克风保持关闭，以及挂断后的 PASSIVE/SLEEP 恢复行为见[语音交互子系统](16-voice-interaction.md)。

## 实施状态

当前 UI/API 主要用于 simulator。simulator 的移动技能标记 `confirm`。未配置 `SafetyReviewer` 时，Agent 不能执行确认级技能；已登录的 Dashboard 操作员确认后可以执行。Go2 profile 暴露 SportClient 动作。Go2 是成熟的量产机器人，自带平衡与基础避障，风险分级看动作是否需要大片空场、能否靠避障化解，不按动作名一刀切。分级已同步到 `adapters/unitree_go2/actions.py`、profile JSON 与测试，测试要求 profile 与动作表逐项一致。当前分级：姿态、步态、限时移动、舞蹈、摔倒恢复等常规动作为 `normal`；前空翻、后空翻、侧翻、向前跳、向前扑、倒立、自由弹跳、自由跳跃这类需要大片空场、避障无法化解风险的动作为 `confirm`；`sport.switch_avoid_mode`、手柄控制源（`sport.switch_joystick`）和自动恢复开关（`sport.auto_recover_set`）也是 `confirm`。`confirm` 动作的调用入口包含 Agent 与 Dashboard，不再设置操作员确认标志：Agent 经无工具 AI 复核，Dashboard 经操作员确认。Go2 目前没有 `high` 动作；`high` 只留给关闭安全保护的操作（如 `SwitchSet(false)`），这类操作尚未暴露。`Damp` 没有暴露。simulator 的 `base.move_distance` 保持 `confirm`：它是测试台里唯一的确认级技能，复核通过、复核拒绝、digest 绑定和复核器缺失等测试都依赖它。代价是未配置复核器时 Agent 在 simulator 上不能移动，端到端测试要么配置复核器，要么由 Dashboard 操作员确认。所有公开 API 方法的策略清单仍需逐项审阅。

Dashboard 通话的第一方代码、单通话 WebRTC 媒体端点和浏览器控制已进入主仓库。通话租约由 Voice Service 音源仲裁器提供，本地音频设备必须先关闭并释放；模型/运行包下载和目标板安装见[部署指南](../deployment-guide.zh-CN.md)。浏览器端 `aiortc`/PyAV ARM64 wheel、麦克风/扬声器路由、实机低延迟及 10 小时稳定性仍未验证。

复核结论、方向证据和本地执行条件已经进入 Runtime 安全门禁；总览中的安全门禁指标显示通过、需要证据、否决和条件失败计数。对 `sport.switch_avoid_mode` 与 `sport.auto_recover_set` 的 Dashboard 挑战会要求重新输入当前账户密码，并绑定一次性、限时的具体动作。
