# Agent 与工具调用

## 职责边界

机器人运行时 Agent 使用云端模型提供语义理解、自然语言对话、任务拆解和技能选择；Agent 作为工具循环和上下文管理层，机器人专用逻辑通过受限工具接口暴露。运行时 Agent 的具体实现尚未冻结，Pi 是待评估候选。

PicoClaw 当前仅用于替代 Pi coding agent 的先行方案，负责隔离工作区中的插件/补丁开发，不承担机器人任务规划或运行时工具循环。两种 Agent 的模型路径、权限和验收标准分别管理。

Agent 不直接操作硬件协议，不维护机器人权威状态，不自行认定动作已经完成，也不承担实时避障、平衡或急停。事务处理流回环负责将工具调用转为可执行命令，并等待真实反馈。

## 端云模型路径

MVP 只配置一个明确的模型调用路径，避免同一轮任务经多个互相不知情的 LLM 循环反复规划：

1. 所选运行时 Agent 直接通过选定 provider 调用云端模型；或
2. 所选运行时 Agent 调用一个受控云端 AI Gateway，由 Gateway 代理模型请求。

Dashboard 设置页把这一条路径记在本机 `config/llm.json`：provider、base_url、model、timeout 和 API key。API key 只保存在该文件中，不回显到接口或日志。当前规则型 DemoAgent 不调用这份配置；后续运行时 Agent 只读取这一份，避免再增加第二条模型路径。

图像/语音感知服务可作为独立模型服务，但必须输出有版本的结构化观测。Agent 的任务模型调用和专用感知模型调用需在追踪里区分。

本地不部署 LLM。断网时运行时可以完成本地安全动作、取消或等待；若无云端能力，应明确告诉用户任务暂不可继续，不用本地小模型静默替代。

## 工具设计

工具表达高层技能而不是电机控制。建议命名稳定、参数类型明确、范围可验证，例：

- head.look(yaw_deg, pitch_deg)
- base.move_distance(distance_m, max_speed_mps)
- speech.say(text)
- navigation.go_to(named_location)
- task.get_status(task_id)
- task.cancel(task_id)

工具集合按机器人能力动态提供；未声明的技能不提供给模型。参数 schema、限制和用户确认要求由适配器能力清单与安全策略生成，不应只依赖提示词约束。

工具返回应表示已受理或拒绝，并携带 task_id/command_id 以及查询进度的方法。工具响应不是最终自然语言答复的证据；Agent 要根据回环汇总的执行反馈和评估结果回复用户。

## 决策上下文

发送给云端模型的上下文应是与当前任务相关的摘要，包括：

- 用户目标和对话必要上下文。
- 当前机器人、可用技能和限制摘要。
- 最新且未过期的感知状态与数据来源/置信度。
- 当前任务进度、动作结果、失败原因和已尝试步骤。
- 隐私允许范围与需用户确认的操作。
- 获得授权且与当前任务相关的用户偏好/记忆，以及它们的来源和更新时间。

不要在每轮默认发送完整原始传感器流或全部长期记忆。上下文中区分“观察到”“估计为”和“模型推断”，避免将推测呈现成事实。

Agent 可依据反馈分析误唤醒、漏唤醒或交互成功率，并提出 profile 调整建议。MVP 中 Agent 没有写入生效配置的工具；配置变更进入独立提案与验证流程，不能直接变更本地安全规则。

## 重试、超时与幂等

- 模型请求、工具请求和动作命令使用独立的超时与关联 ID。
- 对话生成可按 provider 策略重试；动作不得因模型重试而重复执行。
- 使用 command_id 去重；对不可幂等技能默认不自动重发。
- 模型超时后由事务流决定等待、取消待执行命令或返回可恢复错误。
- 未知/不支持的技能请求应拒绝并给出能力摘要，不允许模型编造后备硬件命令。

## 未来扩展

VLA 或专用策略模型可作为一个技能实现接入，例如 manipulation.pick。其输入/输出仍通过适配器与回环契约，输出需经过本地安全和能力约束。是否使用 VLA 应由具体任务的成功率、延迟、算力、数据与硬件兼容性评估决定，不作为 Agent 基础架构的前提。
