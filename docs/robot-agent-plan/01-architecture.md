# 总体架构

## 架构原则

采用云端语义决策、本地确定性执行的端云分工。云端承担上下文理解、任务拆分和技能选择；机器人本地承担设备驱动、快速控制、安全监督和断连降级。系统不要求本地大语言模型。

三大业务模块保持明确边界：

- 机器人适配器负责硬件协议与标准事件/技能契约之间的转换。
- Agent 负责语义决策及经过约束的工具调用。
- 事务处理流回环负责任务状态机、数据路由、反馈融合、重试/取消策略和结果评估。

共享契约、身份与权限、配置、追踪和审计是横向治理职责。

  L --> A[云端 Agent / Pi 工具循环]
  A --> I[受约束的技能意图]
  I --> L
  L --> G[动作适配器与本地安全监督]
  G --> R[机器人技能/控制器]
  R --> F[动作反馈与新观测]
  F --> L
  L --> Q[任务评估与结果]

## 组件职责

### 机器人适配器

分为感知适配器和动作适配器，可由同一个设备插件同时实现。它负责设备连接生命周期、原生协议映射、单位/坐标转换、健康状态、时间戳和能力描述。它不得把原始硬件消息协议泄漏给 Agent。

部署配置 `config/robot.json` 选择静态登记的 `robot_module`；模块目录为 `adapters/<robot_code>/`，并由模块清单提供默认 profile。适配器 registry 只映射允许的模块 ID 到 factory，不从配置动态导入代码。Profile、厂商驱动 bridge 和机器人专属 `third_party/` 都归该模块所有。连接后仍须校验设备身份、协议版本和实际能力；配置不能创造尚未实现的厂商协议或动作语义。详细约束见[机器人模块组织规范](12-robot-module-standard.md)。

### Agent

接收经过筛选的任务上下文和最新状态摘要，调用云端模型并通过工具接口提出高层技能请求。Agent 不直接发原始驱动命令、不拥有任务最终状态，也不能绕过本地安全检查。

### 事务处理流回环

创建并关联任务，路由感知事件，更新状态估计，管理从唤醒到任务创建的交互状态，控制 Agent 调用时机，验证命令与权限，等待动作进度，融合新反馈，判断目标是否完成，并决定继续、重规划、取消或返回结果。空闲主动任务也由此流创建，但必须先通过本地资格策略。

记忆和策略改进不构成新的硬件控制通道。事务流将已授权记忆提供给 Agent；Agent/云端模型可提出唤醒策略候选，另经验证和批准流程发布新 profile 版本。

### 本地执行和安全

这是适配器/机器人运行时的必要职责，不是第四个业务模块。运动控制、避障、速度/区域约束、急停、控制器 watchdog 和断连策略在本地执行，且不依赖云端模型可用。

启动监督器/恢复管理器是部署运行时的基础设施进程，不是第四个业务模块。它独立于 Agent 和可变业务代码，负责启动健康检查、切换已知良好发布版本并进入安全恢复模式；不执行机器人高层决策。

## 部署建议

MVP 将事务流、Agent 客户端和适配器编排放在一个机器人侧运行时中，每个运行时实例绑定一个 robot_id 和一个由 `config/robot.json` 选择的机器人模块/profile；该机器人可以挂接多个传感器和执行设备。切换机器人通过配置选择其他已登记模块，不在 core runtime 添加厂商分支；本项目不包含多机器人集中调度或机器人间协同。云端只暴露模型 API。服务边界先通过模块接口建立，不以微服务拆分作为 MVP 目标。

首台真实机器人优先评估 Unitree Go2，并以模拟器完成接口先行验证。阶段 0 需实测确认可用 SDK/驱动路径、通信方式、传感器和技能，方案不预设具体 Topic/API。第二个兼容型号/profile 在隔离环境中用来检验配置化边界；如它属于不同协议族，则应预期增加适配器代码。这是兼容性测试，不表示一个运行时实例连接多台机器人。

云端与机器人 Gateway 使用受认证和加密保护的 HTTPS/WebSocket/MQTT 等应用层链路。若设备使用 ROS 2，ROS 2 适用于本地机器人域内通信；不要将 DDS/ROS Domain 未加防护地暴露到公网。

摄像头注意力、手势检测和语音采集可分成低成本/低延迟的触发检测与云端语义理解两层。触发信号先在本地形成短时会话状态；只有采集到用户语音或明确确认后才创建命令任务。触发检测可使用设备能力或专用感知服务，不要求本地大语言模型。

地图/熟人记忆、用户偏好、机器人策略、插件/代码发布包、密钥凭证和恢复元数据使用分离的存储与权限。Git 管理代码和可版本化配置，不作为记忆/密钥数据库，也不通过无条件重置工作树执行恢复。

## 关键数据类别

| 类型 | 示例 | 生产者 | 用途 |
|---|---|---|---|
| 观测 observation | 主人出现，方位角 20°，置信度 0.91 | 感知适配器/控制器 | 更新状态 |
| 状态 state | 主人在视野内，最后更新时间 | 事务流 | 形成决策上下文 |
| 意图 intent | 转向主人方向 | Agent | 表达高层选择 |
| 命令 command | 执行 turn_to(angle=20°) | 事务流校验后 | 请求执行技能 |
| 反馈 feedback | running、succeeded、当前姿态 | 动作适配器 | 更新执行状态 |
| 评估 evaluation | 目标已达成/未达成及证据 | 事务流 | 完成或继续任务 |
