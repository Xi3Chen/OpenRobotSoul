# 唤醒词残段进入 ASR 转写：问题与方案

状态：方案讨论（未选型落地）  
关联：[16-voice-interaction.md](16-voice-interaction.md)、`robotsoul/voice/commands.py`、`robotsoul/voice/service.py`、`robotsoul/voice/engine.py`

## 1. 现象

实机语音日志中多次出现：

1. **本地 KWS 已正确唤醒**（日志有「唤醒：索拉」），随后 ASR 最终转写仍把称谓带进整句，且写成近音错字。  
   例：`左拉，向后转。`、`佐拉站起来。`
2. **闭集口令因此匹配失败**。当前闭集先做「精确剥除配置唤醒词」，剥不掉时整句无法命中 `站起来` / `向后转` 等规则。
3. **失败后掉进语言决策**。开放路径依赖 LLM；对话上下文压缩时出现  
   `summary provider returned an empty result`，任务以失败结束，动作未执行。
4. **临时修补暴露可维护性问题**。为应付「左拉/佐拉」等，曾在代码中增加硬编码同音表与启发式；换机器人称谓后这些表立刻失效或误伤，不合理。

典型链路（失败）：

```text
KWS: 索拉 ✓
ASR: 「佐拉站起来。」
闭集: 无法剥「佐拉」→ 不命中 sport.stand_up
语言决策: 进入 LLM / 摘要 → empty result → failed
```

期望链路：

```text
KWS: 索拉 ✓
指令文本: 「站起来」或语义等价
闭集或语言决策: 执行 sport.stand_up
```

## 2. 原因

### 2.1 架构分层已对，边界实现未闭合

文档 [16](16-voice-interaction.md) 与实现已经区分：

| 层 | 职责 | 现状 |
|---|---|---|
| KWS（sherpa-onnx） | 在音频上检测配置唤醒词 | 可用；日志证明命中 |
| ASR | 唤醒后转写用户指令 | 仍可能把唤醒段/回声/连读写进文本 |
| 闭集 / LLM | 理解「站起来」等意图 | 依赖「干净指令文本」 |

问题不在「系统不会判断同音」，而在 **把「ASR 文本里的错写称谓」当成了要在闭集规则里用字符串穷举解决的事**。

### 2.2 ASR 对人名/造词称谓天生不稳

专有名、品牌名、自造称呼（如「索拉」）是 ASR 弱项。同音异字（佐拉、左拉、所拉）在语言模型里往往比生造词更「像真实词」，故被优先输出。这与是否换称谓无关：**任意新称谓都会再产生一批新错写**。

### 2.3 闭集匹配当前只精确剥唤醒词

`match_closed_command` 的 `_normalize` 只剥配置字面量（如「索拉」）。  
`service._is_wake_only` 已对「整句仅唤醒词」做了无调拼音判断，但 **「唤醒残段 + 指令」的前缀剥离** 没有同等的通用拼音逻辑，却叠了硬编码别名。

### 2.4 硬编码同音表为什么不合理

- 与 `config/voice.json` 的 `wake_phrase` / `robot_name` 解耦失败：换名不换表 → 静默失效。  
- 表永远追不上 ASR；每出现一个新错写就改代码、发版。  
- 过宽启发式（按尾字、按长度砍前缀）会误伤真指令。  
- **同音/近音判断应绑定「当前配置的称谓」动态计算，或交给语义层，而不是仓库常量。**

### 2.5 次生问题：摘要空结果

闭集失败后进入对话进程；上下文压缩调用 summary provider 返回空内容时，整单失败。这是开放路径的稳定性问题，会放大「唤醒残段」的用户感知，但不是根因。根因仍是：**本可闭集执行的口令没有得到干净指令文本**。

## 3. 业界常见做法（摘要）

1. **唤醒与 ASR 解耦（主流推荐）**  
   专用 KWS 听音频；唤醒后再开 ASR。尽量让 ASR **不要吃到唤醒词对应的那一段音频**（时间裁剪 / pre-roll 起点后移）。Picovoice 等明确反对用通用 ASR 兼做唤醒。

2. **转写侧按「当前唤醒词」动态剥离**  
   - 精确剥配置串（你们已有）。  
   - 中文用 **拼音（常去声调）+ 相似度/编辑距离**，相对当前 `wake_phrase` 动态生成，不维护死表（如 pinyin-wakeword、音素热词纠错思路）。  
   - 或 Levenshtein 相对 keyword（Kiwi Voice text engine）。

3. **开放语义交给模型**  
   ASR 纠错 / NLU 可向 LLM 提供文本 + 拼音锚点，由模型消歧同音。适合非闭集、多轮对话；不适合也不必要用硬编码表支撑闭集。

4. **数据驱动别名（仅作运维补充）**  
   原型阶段有人从日志收集近音并写入配置。可接受为 **部署配置/运营数据**，不可接受为与称谓绑定的源码常量。

## 4. 方案对比

### 方案 A：音频裁剪（治本）

**做法**：KWS 给出唤醒结束时间（或固定延迟）；ASR 只上传该时刻之后的 PCM（可保留短 pre-roll 以免吞掉指令首字）。文本侧仍保留精确剥配置唤醒词作为双保险。

| | |
|---|---|
| 优点 | 从源头减少「佐拉」进入转写；与换名无关；符合 16 号文档分层 |
| 缺点 | 依赖 KWS 时间戳/延迟标定；裁太狠会吞「站」等首字；需实机调 pre-roll |
| 工作量 | 中（采集链路与时间对齐） |
| 风险 | 标定不准导致指令残缺 |

**适用**：中长期默认方向；与现有 sherpa KWS 匹配。

### 方案 B：相对当前唤醒词的拼音动态剥离（治标、可换名）

**做法**：删除 `_WAKE_ASR_ALIASES`。对转写句首、与 `wake_phrase` 同长度（或同音节数）的片段做无调拼音相似度；超过阈值则剥掉，再跑闭集。可复用 `service` 里已有的 `_toneless_pinyin` 思路，扩展为「前缀剥离」而非仅「整句是否纯唤醒」。

| | |
|---|---|
| 优点 | 换称谓只改配置；无死表；闭集继续低延迟 |
| 缺点 | 阈值需调；极端近音仍可能误剥；解决不了 ASR 把整句听飞的情况 |
| 工作量 | 小～中 |
| 风险 | 误剥真指令前缀（需命令起始约束或高阈值） |

**适用**：在 A 落地前的必要文本兜底；也可与 A 长期并存。

### 方案 C：闭集失败即交给 LLM（语义层同音判断）

**做法**：不在闭集里做同音表。剥不干净或未命中时走语言决策；系统提示中写明当前机器人称谓，要求忽略称谓的 ASR 错写。可选用「文本 + 拼音」提示增强（业界 ASR 纠错常见）。

| | |
|---|---|
| 优点 | 真正「AI 判断读音/意图」；换名只改配置与提示 |
| 缺点 | 多一次云端调用；延迟与费用；摘要/LLM 空结果会直接导致失败（现状已暴露） |
| 工作量 | 小（提示）～中（拼音锚点 + 摘要容错） |
| 风险 | LLM 不稳时简单口令也失败 |

**适用**：开放指令与兜底；**不能单独替代** A/B 对「站起来」等高频闭集的保障。需同时修 summary 空结果 fail-closed。

### 方案 D：配置/运营同音表（不推荐作主方案）

**做法**：`wake_phrase` 旁增加 `wake_aliases`，由日志运营追加。

| | |
|---|---|
| 优点 | 实现简单；可按部署定制 |
| 缺点 | 仍是枚举；换名要迁表；与「不要代码写死」本质同类，只是挪到配置 |
| 工作量 | 小 |
| 风险 | 表膨胀与误触发 |

**适用**：仅作 B 的可选补充，不作为主路径。

### 方案 E：继续源码硬编码别名（否决）

已验证不合理：换称谓即出 BUG；与配置化唤醒词目标冲突。**不采纳。**

## 5. 建议路线

1. **立即**：去掉源码内 `_WAKE_ASR_ALIASES` 及依赖它的启发式；避免制造「换名即坏」的技术债。  
2. **短期**：落地 **方案 B**（拼音动态前缀剥离）+ 闭集前统一「清洗转写」入口；并给语言路径补称谓说明，减轻残留错写。  
3. **中期**：落地 **方案 A**（ASR 音频起点后移 / 按 KWS 时间裁剪），从根上减少残段。  
4. **并行**：修对话 **summary 空结果** 的 fail-closed（重试、跳过压缩、或降级无摘要决策），避免次生失败掩盖语音问题。  
5. **原则**：  
   - 闭集：吃「清洗后的指令」，清洗算法只依赖**当前配置的唤醒词**，不依赖仓库常量人名表。  
   - 开放域：同音与意图交给 LLM（可加拼音锚点）。  
   - 配置换名：只改 `voice.json` / `robot.json`，行为自动跟随。

## 6. 验收标准（方案落地后）

- 配置唤醒词为「索拉」时：ASR 返回「佐拉站起来」「左拉，向后转」仍能闭集到正确技能（在 B 或 A+B 下）。  
- 将唤醒词改为另一双字称谓（如「小月」）后：**不改代码**，同音错写（如「晓悦站起来」）仍能剥前缀并闭集命中。  
- KWS 命中且指令为标准口令时，不因 summary 空结果导致整单失败（开放路径降级策略生效）。  
- 无针对特定旧称谓的源码常量表。

## 7. 非目标

- 不在本方案用通用 ASR 替代 KWS。  
- 不承诺单麦克风下「不唤醒也能可靠区分是否对机器人说话」（见 16 号文档）。  
- 不把 LLM 作为每一帧音频的同音判决器。
