# 运行日志

运行日志是给操作员看的纯文本记录，用来区分是哪个模块、在什么时间、以什么严重等级打出的一条消息。它不替代工具调用审计，也不保存原始音频。

## 文件

日志目录是仓库下的 `logs/`，不纳入版本控制。文件按本地日期命名，例如 `logs/2026-11-13.log`。过了零点之后写入新的一天的文件。不把旧文件改名为 `runtime.jsonl.1`，也不再写 `logs/voice_events.jsonl`。

每一行都是一条完整记录，前缀包含本地时间、模块和等级：

```text
[2026-10-16-6:30:59.320-Gateway-Error] XXXXError
```

- 时间格式为 `年-月-日-时:分:秒.毫秒`，毫秒三位。
- 首批模块名是 `Dashboard`、`Runtime`、`Voice`。
- 等级只有 `Info`、`Warning`、`Error`。
- 前缀后面是一条消息。换行会被收成空格，消息最长 1000 字。

文件权限为仅当前用户可读写。追加后执行 fsync。写入失败不会让语音识别或控制流程退出。

## 写入范围

- 运行时创建后记录 profile、机器人、模块、Agent 和可用能力数量，并再记一次连接是否完成。
- Dashboard 记录操作员目录、开始监听和停止。地址、端口和语音服务是否接入会写在监听记录里。
- 语音服务记录音频后端、语音服务启动、本地麦克风打开结果，以及唤醒、识别、端点和合成模型的开始与完成。任一模型失败会记一条 `Error`，成功结束时记「语音模型加载完成」。
- 语音服务进入被动监听或休眠、打开麦克风失败、通话建立、接通、断开、恢复和结束，以及播放失败。
- 唤醒命中记一条，例如 `[2026-11-13-18:52:01.320-Voice-Info] 唤醒：索拉`。唤醒之后和通话期间，识别文本发生变化时再记一条「识别中」；端点确定的文本记一条「识别」，例如 `识别：向前（本地麦克风）`。同一句里没有变化的文本不重复记录。最终文本接着记「提交运行时」。运行时返回后记完成、失败和原因，回复结束后记「回复结束，等待后续指令」。会话已更换而没有提交或没有播报时记一条 `Warning`。原始音频和每个音频帧不记录。
- 运行时处理一条文本时按顺序记录：收到指令、直接指令或等待语言决策、已选择技能、需要复核时的开始和通过、开始执行、执行完成或取消。任一环节没有执行时记 `Warning`，带上原因。技能参数原文不写入运行日志。

不记录每个音频帧、波形采样、PIN、密码、密钥或工具参数原文。如果消息里出现 `password=`、`token=` 这类赋值，值会被替换成 `[redacted]`。

## 和另外两类记录的分工

- `logs/tool_calls.jsonl` 仍是工具调用审计，记录技能调用是否被允许和执行结果。运行日志不合并这份审计。
- 不再单独保存语音事件 JSONL。唤醒和最终识别只出现在当天的运行日志里。
- 总览页不展示语音日志。监控页勾选「日志」后，通过已登录会话读取 `GET /api/logs`，直接显示带前缀的文本行。

`GET /api/logs` 默认返回当天最新 100 行，`limit` 取 1 到 200，可选 `level=Info|Warning|Error`。未登录不能读取。
