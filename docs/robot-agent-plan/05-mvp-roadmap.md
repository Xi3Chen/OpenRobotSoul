# MVP 实施路线

## 阶段 0：技术选型与契约冻结

交付：

- 选定首台机器人/模拟器、传感器、云端模型 provider 和部署位置。
- 将 Unitree Go2 列为首发实机候选；在确认 SDK/驱动、连接和安全控制条件后冻结具体路径。
- 记录 PicoClaw 的版本、license、模型/provider 接口和工具扩展方式。它只承担隔离工作区中的编码任务。自然语言规划由 `robotsoul.language_gateway` 承担，两类工具面分开登记。
- 明确技能清单、事件 schema、任务状态机和安全边界。
- 定义机器人 profile schema、型号身份校验和配置覆盖优先级。
- 为关键未决事项创建 ADR，不在业务代码里隐式做长期架构决定。

验收：端到端接口草图通过机器人控制、安全和云端 API 约束检查；最小延迟与成本基线有测量方案。

## 阶段 1：契约与模拟适配器

交付：

- 观测、状态、能力、命令、反馈和评估的数据类型。
- Fake/simulator adapter，支持模拟传感器事件和 2-3 个技能。
- 至少两个模拟机器人 profile，其中能力集合或限制存在差异；每次测试实例只加载其中一个 profile。
- 任务状态机和 trace/task/correlation ID。

验收：重复运行固定场景可预测；非法参数被拒绝；命令状态按生命周期变化；超时/取消可测试；切换 profile 不需要改 Agent 或事务流代码，且不支持的技能不会暴露。

## 阶段 2：单机器人云端 Agent

交付：

- `robotsoul.language_gateway` 接入 `config/llm.json` 中的云端模型 API，作为文本与语音最终转写的共同规划器。Go 版 PicoClaw 不读取这条运行时规划配置。
- 自然语言任务、工具 schema、技能白名单和能力上下文。文本框和语音最终转写使用同一入口。
- 单一端到端技能执行路径以及用户结果答复。

验收：模型无法调用未注册技能；模型工具重试不会重复执行物理动作；云端超时可安全结束。

## 阶段 3：真实动作反馈与评估

交付：

- 真实动作适配器及本地安全监督。
- accepted/running/succeeded/failed/cancelled 反馈映射。
- 传感器/里程计/控制器状态参与任务评估。

验收：实际执行结果与任务评估一致；本地急停、低速限制和云端断连策略在实机/仿真中通过验证。

## 阶段 4：交互唤醒与语音任务输入

交付：

- 作为独立 Voice Service 子系统交付设备发现、单音源租约仲裁、中文小型 KWS、VAD/流式 ASR、轮次管理和健康监督；模型在唤醒后不重新加载。
- 部署配置机器人显示名/唤醒短语和模型 ID；无通话且无本地麦克风时进入 SLEEP，不运行识别器。
- Dashboard 认证通话通过 HTTPS/WSS/WebRTC 输入；通话接管前关闭并释放机器人麦克风，挂断后重新探测并恢复 PASSIVE 或 SLEEP。
- 先针对目标板定义并实测低延迟预算和 10 小时长跑指标；具体组件契约和状态机见[语音交互子系统](16-voice-interaction.md)。
- 可选地在独立阶段增加视觉注意力信号，作为唤醒条件之一，而非身份认证。
- 设备专用适配器将检测、转写和取消映射为规范事件；事务流实现 idle/listening/timeout/clarification 状态。
- 事件有效期、来源、置信度及隐私分类进入交互策略。

验收：通过音源并发/切换契约测试、无设备休眠测试、媒体断线恢复测试、目标板时延测试和至少 10 小时混合负载测试；唤醒短语或挥手后说话能形成 Agent 任务；只有挥手、低置信/过期事件、无语音、多人歧义和超时不会误发动作。说话对象不明确时回到 PASSIVE 或要求再次唤醒。摄像头/麦克风提示、授权和数据保留策略已验证。

## 阶段 5：记忆与受控自我改进

交付：

- 用户偏好、短期任务上下文和历史任务结果分层存储。
- 单实例下 robot_id/device_id 的数据隔离与显式读取/遗忘策略。
- 误唤醒/漏唤醒指标、带证据的策略变更提案、回放/影子测试、维护者批准、版本部署与回滚。
- 增加第二种传感器适配器，或在独立测试部署中增加第二个机器人型号 profile，用以验证契约可复用性。

验收：Agent 不能直接写运行配置；未经授权的变更不生效；获批的 profile 版本可以回滚。记忆错误、过期和删除行为均可测试。同一适配器支持的第二型号可以只增加/切换配置；新协议可新增适配器但 Agent 和事务核心不写厂商分支。

## 阶段 6：受限主动行为

交付：

- 本地主动任务资格策略，基于电量、健康、任务队列、环境风险、用户偏好/静音时段和允许区域判断。
- 先实现低频、可取消的问候；再在已知且授权的区域实现限速、限时、限距离探索。
- 用户呼叫、障碍/人员风险、低电量、传感器故障、急停或云端失联时的中止流程。

验收：任一资格不满足时不创建主动任务；执行中条件失效时本地停止/暂停；Agent 不可扩大区域和动作边界；主动问候遵守频率上限和免打扰设置。

## 阶段 7：环境记忆与能量管理

交付：

- 经定位/建图能力验证的地图候选更新、版本比较和禁区保护。
- 经用户授权的熟人目录、最近交互和招呼偏好；提供确认、查看和删除。
- 低电量、返航余量、充电点可达性、求助和 savepower 状态机。

验收：地图候选不能扩大授权区域；未经确认的人不进入熟人目录；低电量决策按设备反馈完成返航/充电、求助或 savepower，不能只按工具返回推断成功。

## 阶段 8：启动监督与自恢复

交付：

- 独立 Supervisor、last-known-good 发布槽、启动健康检查和恢复模式。
- 本地自动回滚、重复崩溃隔离、恢复日志和断网安全待机。
- 云端诊断提案的隔离工作区、测试门禁和授权发布流程。

验收：损坏版本启动失败时断网也能安全回退；当前版与 last-known-good 都失败时进入恢复模式而非无限重启；修复流程不会覆盖记忆、地图或凭证。

## 阶段 9：插件扩展与受控代码改进

交付：

- 插件声明、风险分类、权限沙箱、签名包和确定性发布门禁。
- PicoClaw 在隔离工作区生成插件/补丁；低风险预授权插件通过门禁后可自动 canary 部署，其他变更走批准流程。先完成编码能力、权限隔离和工具协议评估，再启用部署链路。

验收：仅在阶段 8 恢复机制通过后启用自动发布；L0/L1 预授权插件通过自动门禁后可部署并可回滚；新增动作权限、唤醒策略及核心代码未经批准不部署。

## 推进顺序与退出条件

每阶段先完成上一阶段的自动化验收，再把硬件动作风险提高一级。任一阶段若任务状态无法从反馈可靠确定，应先修复反馈或可观测性，不进入自动重试或扩大动作范围。

方案已锁定由常驻语言进程 `robotsoul.language_gateway` 规划全部自然语言交互，包括文本任务和语音最终转写。消息总线和微服务拓扑仍不锁定。语言进程与 Go 版 PicoClaw 的边界、自然语言工具面和编码隔离见 [Agent 选型与 PicoClaw 集成决策](11-agent-tooling-decision.md)。
