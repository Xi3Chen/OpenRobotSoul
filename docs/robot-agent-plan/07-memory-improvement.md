# 记忆与受控自我改进

## 目标与边界

记忆帮助机器人在经授权的情况下保留偏好和交互历史；自我改进流程利用运行证据提出策略调整。两者不能与正在生效的运行策略混为一类。

PicoClaw 的编码任务可以在隔离工作区编辑文件，这不等于自然语言会话可以直接修改传感器配置。自然语言会话可以分析事件和指标、生成变更提案；代码生成与插件打包仍只在隔离的开发/扩展流程执行，并且该会话不能调用机器人技能。只有明确列入预授权 allowlist 的低风险插件变更可以在自动化门禁通过后自动部署。自然语言会话不持有安全策略、设备权限或生效代码的直接写权限。

## 三类数据

| 类别 | 内容 | 是否直接影响运行 |
|---|---|---|
| 记忆 memory | 用户明确保存的偏好、已确认身份关联、交互结果摘要、技能成功/失败记录 | 仅作为带来源和有效期的上下文；不改变设备阈值 |
| 改进提案 proposal | 针对误唤醒、漏唤醒、延迟或体验问题提出的配置/代码差异和依据 | 否，按风险策略验证；低风险预授权插件可自动发布，其他变更需批准 |
| 运行策略 policy/profile | 当前生效的唤醒触发、采集窗口、冷却、主动行为限值和机器人能力配置 | 是，由受信任部署流程版本化发布 |

记忆记录应包含来源、创建/更新时间、置信度或确认状态、用户/机器人归属、敏感级别、保留期限及删除状态。用户可查看、更正和删除可持久化的偏好。临时任务上下文与长期偏好分开存储。

## 自我改进闭环

1. 收集最小化的脱敏运行指标，例如触发后无语音的比例、用户取消率、唤醒后任务完成率和显式的“不是在叫你”反馈。
2. 在足够样本和可解释证据基础上，由 Agent 生成 proposal，说明目标、配置差异、预期收益、风险、适用传感器/型号及回退条件。
3. 对提案执行 schema 校验、能力兼容性检查和硬安全边界校验。拒绝任意代码、未声明字段以及会放宽安全边界的修改。
4. 使用录制回放/离线样本比较当前策略和候选策略；可行时运行 shadow mode，只计算候选结果，不改变实际触发或动作。
5. 确定性风险策略检查变更能力、设备权限、数据访问、运动影响和代码范围。模型不得自行声明变更为低风险。
6. 若变更仅在已批准的低风险插件 allowlist 内、权限不增加且所有自动化门禁通过，可进入自动部署；其他变更须由用户/维护者批准具体差异。授权范围、批准人、时间和证据写入审计记录。
7. 发布为不可变的新插件/profile/policy 版本，先在目标机器人上 canary；旧版本保持可恢复。
8. 监测误唤醒、漏唤醒、交互延迟、取消率和安全事件。若超过回滚条件，自动恢复上一个已知良好版本并告警。
9. 将新一轮结果用于后续建议，不自动把提案结果伪装成用户事实记忆。

## 不可自改的项目

无论模型信心或历史结果如何，Agent 都不能自行更改：

- 急停、避障、碰撞保护、速度硬上限和安全区域边界。
- 摄像头/麦克风隐私开关、身份认证和用户授权状态。
- 访问控制、密钥、数据保留/删除策略和用户拒绝/免打扰设置。
- 适配器代码、驱动二进制、profile 中已验证的硬件能力以及工具权限集合。

唤醒算法/阈值变更、探索区域扩展、增加设备权限或改变数据采集范围均需用户/维护者批准；若变化影响个人数据处理方式，还需额外明确授权。自动部署只适用于 allowlist 中已预授权的低风险插件，不适用于这些策略变更。

## 版本与回滚

策略版本不可原地覆盖，至少记录 profile_id、版本号、父版本、配置摘要、变更差异、来源（人工/Agent 提案）、批准记录、测试证据和发布时间。启动时验证签名/摘要、schema 版本、适配器兼容范围和设备型号；验证失败时拒绝加载新版本并保留上一个已知良好版本。

回滚恢复先前策略版本，不撤销已发生的物理动作。回滚后仍需按本地安全控制确认机器人状态。

## MVP 验收

- Agent 只有读取授权记忆和创建 proposal 的工具，没有修改运行配置或发布插件的直接工具。
- 低样本、无证据或违反硬约束的提案被拒绝。
- 离线回放或 shadow mode 能比较候选和当前策略。
- 未批准的唤醒策略/核心代码变更不会生效；在明确 allowlist 内的低风险插件可自动发布并产生完整审计记录。
- 部署后指标退化能触发回滚；旧版本恢复后策略行为与基线一致。
- 用户记忆删除后不再注入 Agent 上下文；指标仅按已声明保留期限保存并可识别地去标识。
